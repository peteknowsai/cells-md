What it is

Until now the fleet had no single cockpit. cells list is a flat dump; the web dashboard (cells-dashboard.cells.md) is a glanceable wall, not a place you act from. cells agents is the terminal command center: a full-screen, live, keyboard-driven view of every cell, modeled directly on Claude Code's claude agents — but where Claude Code lists background sessions, this lists cells, and where Claude Code groups by working directory, this groups by project.

It's a thin launcher around the same actions you already have — cells tui, cells talk, cells birth — so it reuses every proven path rather than reimplementing them. Pick a row, press a key, the view steps aside and the action takes the terminal; when it's done, the grid comes back exactly where you left it.

  • Header — fleet counts, the current grouping, and whether welld is reachable (live / welld offline).
  • Operators — the always-on machinery (mother, pulse: special/pinned) always floats to the top, regardless of grouping. It's not project work.
  • Glyph + label — ◆ pinned/operator, ● awake (green), ○ asleep (dim), ⚠ wedged/needs-eyes (red). The label spells it out: awake / asleep / check / wedged.
  • Selected row — the violet ❯ caret. Selection is tracked by cell name, so a 4-second refresh that reorders rows never makes the cursor jump.

The project dimension — the new thing

Cells were addressable by name and organized into colonies, but never grouped by project — the loose "what body of work is this for" bucket you actually think in (homezero, paonia, zero…). That's now a first-class, optional label on the registry, owned Mac-side so the cockpit can group and retag without waking a hibernated cell.

Three ways to set it:

# at birth
cells birth delta-research --project=homezero

# from the shell, any time (omit the project to clear)
cells project delta-market homezero
cells project delta-market none

# from inside the cockpit: select a row, press r, type, ↵

Untagged cells collect under unassigned (sorted to the bottom). Press g to flip the whole view from grouping-by-project to grouping-by-power-state (awake / asleep) and back; your choice rides along as you attach and return.

Two flags: cells agents --by=state opens grouped by power, and cells agents --project=homezero opens scoped to one project. Piped (no TTY), the command prints a one-shot grouped snapshot instead of the live view — handy in scripts.

What "awake / asleep" means (and what it doesn't, yet)

Power comes straight from welld's /dashboard/data: running → awake, stopped/hibernating → asleep, welld unreachable → unknown. Health is welld's wedge field — suspected/confirmed surface as the red ⚠, the cells analog of Claude Code's "needs input": a cell that needs an operator's eyes.

What's deliberately not here yet: a per-cell "working / idle / done" state and a one-line "what is it doing right now" summary, the way claude agents shows a Haiku-generated activity line per session. Cells hibernate when idle and don't report a live activity string today, so the cockpit shows power + health honestly rather than faking a busy/idle signal. Closing that gap (a cell self-reporting a status line on each turn — agent-first, not a poller) is the headline item in the backlog below.

Where the code lives

  • cli/lib/fleet.ts — the canonical fleet loader. Merges registry + pool + welld into a normalized FleetCell[]; pure grouping/sorting/age helpers split from IO and unit-tested in cli/lib/fleet.test.ts.
  • cli/agents-ui.tsx — the Ink view. Render + navigate + retag + regroup inline; attach/talk/birth handed back to the launcher. Mirrors birth-ui.tsx's render/unmount pattern.
  • cli/cells.ts — cmdAgents (the launcher loop), cmdProject (shell retag), the --project birth flag, and the agents/fleet/project dispatch.
  • cli/lib/registry.ts — the new optional project field on Cell.
  • cli/menubar/swift/main.swift — the native macOS status item. Polls cells.json + well list every 10s; a Projects ▸ submenu filters the list to selected projects (multi-select, persisted to ~/.cells/menubar/filter.json; global operators stay pinned). cells menubar install builds + loads the LaunchAgent.

Not yet — the honest backlog

  • Live activity line per cell. A cell reports a one-line "what I'm doing" on each turn (written to its <name>.cells.md push state or a status file), so the cockpit can show it — and split awake into working vs idle. Agent-first: the cell pushes, the cockpit reads. No poller.
  • Peek panel. space currently round-trips into a full talk session; a true in-view peek (last output + reply box, like claude agents) would keep you in the grid.
  • Async birth. n blocks on the birth (mother serializes births anyway — one at a time). A "warming" row that fills in when the birth lands would match the dispatch-and-watch feel.
