Named Durable Sessions + Interactive Talk

One cell holds several independent durable conversations at once (main, buyer ↔ WhatsApp, staff ↔ Slack), each addressable by name. The mechanism is harness-agnostic — every harness uses its own durable-session primitive; the claude-code warm interactive pool is just claude's special case (it exists to win cc_entrypoint=cli billing, which only claude needs).

Status — shipped for claude-code (2026-06-15), generalized to pi + codex (2026-06-16). cells talk <cell> --session=buyer drives a durable conversation isolated from main and staff on any harness. Verified live on a pi cell: durable recall across turns, buyer/staff isolation, main untouched. Per harness: claude-code → the warm interactive pool (cc_entrypoint=cli, opt OUT with CELLS_TALK_INTERACTIVE=0); pi → per-turn pi --print --session-id named-<name>; codex → per-turn codex exec resume <per-name thread>; hermes → unsupported (rejected loudly). pi/codex have no cc_entrypoint billing split (gpt-5.5 on the ChatGPT sub, flat cost), so they need no warm pool — a stable --session-id / thread id makes a plain -p call durable and isolated. Scope: the throwaway fork path (default one-shot cells talk, peer RPC, verify) is unchanged — see Deferred.

Harness-agnostic dispatch (the generalization). The supervisor routes a named-session turn to the pool if it's running (claude-code), else to the adapter's askInSession (pi/codex), else rejects (hermes) — it never silently forks a buyer's message into main. The capability named_sessions (renamed from talk_sessions) is advertised in bridge_hello and is true for the pool or any adapter with askInSession; the per-cell DO gates a non-main session envelope on it (409 if the supervisor isn't named-capable). This unblocks Zero's pi advisors holding buyer/staff sessions — the original motivation, which the pool-only version did not serve.

Why

Two needs land in the same place.

Billing. Anthropic's 2026-06-15 metering split bills claude -p / Agent-SDK on a capped monthly credit, and genuine interactive Claude Code on the normal subscription pool. We already moved jobs onto a genuine interactive runner. But all talk was still --print: the always-on supervisor process and the agent-comms fork path both ran claude --print → stamped cc_entrypoint=sdk-cli → the metered pool. Talk is the bigger leak, because Slack, email, the CLI, and peer target=main turns all funnel through one main session.

Named durable sessions. A HomeZero advisor needs two (eventually N) independent durable conversations on one cell — buyer ↔ WhatsApp (the user) and staff ↔ Slack (operators tuning the cell), never crossing. A cell used to pin exactly one session (/root/.cell/claude-main-session), which is the only reason "main is single-owner."

Both live in the same persistent-process layer, so they're one rewrite. There is no way to keep a persistent stdio stream-json process (which requires --print) and bill cli — so warm interactive sessions, tailing the transcript for output, is the only shape that wins billing. Decided tradeoff: that tail is per-completed-block, not per-token, so live output is message-chunk, not the --print typewriter. Slack/email and agent-comms (which read the text at turn end) are unaffected; the CLI cells talk reveal gets chunkier.

Each LiveSession is one interactive claude in a dedicated tmux -L cell-talk-<name> socket, resuming its durable per-name id, with a per-session queue (same name serializes; different names run concurrently), a transcript-tail loop that emits the same pi-shaped message_update/agent_end lines the old onTranslatedLine did (so Slack/email/CLI/agent-comms are unchanged), Stop-hook turn boundaries, idle eviction, and an LRU warm cap.

Two pi gotchas the live test surfaced (both load-bearing): (1) --session-dir alone only sets storage — pi resumes the project-global latest session, so two names crossed (buyer recalled staff's codeword) until a stable per-name --session-id pinned each one. (2) A bare pi spawn from the supervisor lacks OPENAI_CODEX_API_KEY (only cells-env.sh exports it) so the proxy extension registers no provider, and Bun's spawn even rejected the same --session-id argv a shell exec accepts — so askInSession runs pi through bash -lc (the same shape codex/claude use, and the real fix for the long-standing pi-fork auth gap on this path).

Components

lib/harness-adapters.ts — askInSession
The harness-agnostic half: a new adapter method, sibling of forkAndAsk but the session persists. pi/codex/claude implement it; hermes leaves it undefined (its presence is the cell's named-session capability). The supervisor dispatches to the pool when present, else askInSession, else rejects.
lib/session-pool.ts
Pure seams (unit-tested, no VM): name validation + path safety, main-aliases-the-legacy-pin, resume-vs-create flags, the transcript-row→delta extractor, the finishTurn fallback harvester, idle/LRU policy.
lib/talk-pool.ts
The IO half: tmux launch, the byte-cursor transcript-tail loop, per-session queue + busy reduction, Stop-hook turn close with a poll fallback, crash/leash handling, idle + LRU eviction. Lives in lib/ (not site/) so cells refresh ships it.
bin/interactive-claude-talk.sh
The bootstrapper — sibling of the job runner, but long-lived: seeds the boot gates, registers per-session SessionStart/Stop hooks, launches the tmux, waits for ready, then exits leaving the server alive. The supervisor drives each turn.
site/server.ts
Gated wiring: pre-warm main instead of spawning --print; dispatch named agent_message.session + the raw prompt path to the pool (claude) or askInSession (pi/codex); busy-as-reduction drives welld's busy/idle; bridge_hello advertises named_sessions (= !!talkPool || !!ADAPTER.askInSession); boot sweeps stale talk tmux.
agent-envelope (both copies) + cells talk + the DO
An optional session field threads through the envelope, both CLIs, and the DO's agent_message forward, so a turn can target a named session. --session=main/fork are aliases for the existing target routing.

Reaching a named session

Two equivalent paths, both concurrent-safe (the reply is correlated by corr_id):

# operator / CLI / peer (SSH → on-cell talk → DO → pool):
cells talk <cell> --session=buyer "…"

# pure DO, no SSH (hibernation-robust; what an external bridge uses):
POST https://<cell>.cells.md/inbox/append
  { "kind":"agent", "from":"wa-bridge", "to":"<cell>",
    "corr_id":"…", "text":"…", "session":"buyer",
    "reply_to":"https://wa-bridge.example/hook" }

The HomeZero wa-bridge flips from today's cells talk <advisor> --main to either form with session=buyer — a strict robustness upgrade (the DO survives hibernation and delivers at-least-once).

Tradeoffs & guards

  • Chunk streaming, not token. Intrinsic to dropping --print; accepted. Slack/email/agent-comms unaffected.
  • RAM ceiling. Warm cap = 3 sessions/cell (LRU-evict the least-recently-used idle one); idle-TTL 15 min. An evicted session is durable — the next turn cold-starts and resumes its id. (~1.9 GB per warm claude on the 48 GB Mini.)
  • Jobs stay fresh/fork. Named durable sessions are single-owner, held warm by the pool; a detached job co-writing one would corrupt the live conversation (the same reason main is rejected for jobs). cells run --session remains fresh|fork.
  • Hibernation. On boot/thaw all sessions are treated cold and busy bookkeeping reset; an in-flight turn at hibernation is lost via its leash (same surface as a harness death today). The durable id recovers the conversation.

Verification (delta-market, flag on)

  • Interactive talk end-to-end; the pool's claude runs --resume … --permission-mode bypassPermissions with no --print → cli billing by construction (same mechanism the job runner verified live).
  • Warm reuse: a 2nd main turn returned in ~3s and remembered the 1st turn (durable multi-turn context).
  • Named sessions: buyer recalled a planted secret; staff returned NO-RECORD (isolated); registry files written per name.
  • Warm cap: a 4th session LRU-evicted main, leaving exactly 3 live tmux servers; the evicted session resumed cleanly on its next turn.
  • OFF-path regression: with the flag unset, talk answers via the unchanged --print path.

Rollout

  1. Soak on delta-market (current). Watch billing attribution + talk health.
  2. cells refresh --all (new supervisor + adapter) + redeploy every per-cell Worker (the named_sessions rename — the DO gate reads it) + verify the supervisor_named_sessions advert fleet-wide. The Worker redeploy is required: an old Worker reads talk_sessions (now absent) and would 409 a pi cell's named session. main talk is unaffected in every deploy interleaving.
  3. Tell Zero: the wa-bridge can flip to session=buyer (either reach-path above).

Deferred

  • Fork path → interactive. The throwaway fork (default one-shot cells talk <cell> "…", peer agent-comms, verify) still runs claude --print via forkAndAsk, so that traffic stays on the metered rail. Converting it (a transient interactive fork session, like the job runner's --target fork) is a clean follow-up — deferred because per-fork cold-start adds latency to verify fan-out, a tradeoff worth weighing on its own.
  • Cells-native channel auto-binding — binding a cell's own Slack/email worker channel to a named session (so inbound Slack auto-routes to staff) needs per-session reply routing in the DO (today's single pending-channel can't serve concurrent sessions). Not on Zero's path — they route via the envelope session field above — so deferred.
  • Per-token streaming recovery (no mechanism without --print); keep-alive heuristics for hot named sessions; compaction-aware live streaming (the fallback is correct, just not live).
