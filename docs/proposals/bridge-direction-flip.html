Bridge Direction Flip

Collapse the two-hostname-per-cell scheme to one, by reversing who dials the bridge WebSocket.

Status — shipped 2026-05-22. All six phases executed: the doorbell, the flip, the 8-cell rollout, the dead-path strip, the WebSocket Hibernation API, and the cruft sweep. One addition surfaced mid-rollout — a bridge heartbeat on the supervisor: a hibernated-then-thawed well leaves the supervisor holding a dead socket Bun never raises a close for, so the supervisor pings every 15s and reconnects after three unanswered beats. Two known follow-ups: nfv-market-pi's well is substrate-dead (lume restore-state permission-denied — flipped in code, pending well recovery), and several wells wake from hibernation with a skewed clock (a pre-existing wells-substrate issue, independent of this flip).

Every cell has two public hostnames. This plan removes one of them — and with it the cloudflared tunnel hop, the proxy's well-routing, and the hostname-shape regex that has already caused outages. Nothing about how a cell is used changes. The work is real but stages cleanly; the fleet is migrated one cell at a time.

The problem

A cell is two machines in two places:

The Worker
<cell>.cells.md — runs on Cloudflare, always awake. The cell's public face: its site, its inbox.
The well VM
A little Linux VM on the Mac. Runs the agent. Hibernates when idle.

They keep a WebSocket open between them — the bridge. Today the Worker dials into the VM: its Durable Object opens wss://<well>.cells.md/agent. For a cloud Worker to reach a VM on a home network, every inbound dial has to travel:

Cloudflare → cloudflared tunnel → cli/proxy.ts → welld → VM:8080

That inbound path is why the VM needs its own second hostname (<well>.cells.md, e.g. cells-pulse.cells.md — distinct from pulse.cells.md), why cli/proxy.ts carries well-routing, and why there is a WELL_HOST_RE regex deciding what counts as a well hostname. That regex matched only egg-* wells and silently 404'd cells-* specials — the bug that broke cells talk pulse. The two-hostname scheme isn't cosmetic; it spawns a whole fragile layer.

The fix: reverse the dial

Outbound from a home network is trivial — no tunnel, no NAT punching; it's what every web request already does. So: let the VM dial out to the Worker instead.

The supervisor on the VM opens wss://<cell>.cells.md/agent — straight to the Worker, the same hostname the cell already owns. The Worker accepts it. That deletes the second hostname, the tunnel hop for the bridge, the proxy well-routing, and the regex.

The catch, and the doorbell

The Worker dialing in does a second, load-bearing job: a sleeping VM gets woken by the incoming dial. If the VM dials out instead, a sleeping cell holds no connection — so when a message arrives at the Worker for a sleeping cell, the Worker needs another way to wake it.

Split the two jobs apart. Waking is small — one request to welld (the daemon on the Mac that wakes VMs). Talking is the long-lived bridge. Today both ride the same heavy inbound machinery. After the flip:

  • Talking — the VM dials out. One hostname, no tunnel, no proxy.
  • Waking — a "doorbell": the Worker calls proxy.cells.md/wake, a tiny bearer-gated endpoint that asks welld to wake the cell. proxy.cells.md already has a Cloudflare-to-Mac path (every cell's LLM calls use it) — the doorbell reuses that wire. No new contraption.

Resulting flow for a message to a sleeping cell:

msg → Worker → (cell asleep) → ring proxy.cells.md/wake → welld wakes VM → VM dials in → conversation

Plan of work

Phase 0 — the doorbell · additive, zero risk

Add POST proxy.cells.md/wake to cli/proxy.ts — bearer-gated, body {cell}, resolves the well name and wakes it via welld (the same well start path ensureWellRunningForTalk already uses). Ships and verifies on its own; nothing depends on it yet.

Phase 1 — build the flip · one test cell

  • Worker (cli/worker/cell/) — index.ts handles GET /agent upgrades; cell-agent.ts accepts the inbound WS (plain ws.accept() — the DO stays resident, exactly as it does holding the outbound WS today, so no in-memory state has to move). When /inbox/append arrives with no live WS, ring the doorbell and queue the message.
  • Supervisor (dna/cells/base/site/server.ts) — drop the /agent listener; on boot dial wss://${CELL_NAME}.cells.md/agent with the bearer, reconnect with backoff on drop. The :8080 local server (site, /agent-wait) stays.
  • Prove it end-to-end on one cell before touching the fleet.

Phase 2 — roll the fleet · 8 cells, one at a time

The Worker and the supervisor must agree on direction, so each cell cuts over as a tight unit: deploy the new Worker, push the new server.ts DNA, restart the supervisor. That cell's bridge is down for the cutover window (~30–60s); the rest of the fleet is unaffected. Eight cells, sequential.

Phase 3 — strip the dead path · after all cells migrated

Remove from cli/proxy.ts: isWellHost, WELL_HOST_RE, handleWellHttp, the well WS forwarding. Remove WELL_HOST from the Worker's wrangler.toml template. Remove the stale mother.cells.md ingress from cells-proxy-config.yml.

Phase 4 — hibernation · shipped

Switched the inbound WS to Cloudflare's WebSocket Hibernation API (state.acceptWebSocket) so the DO evicts between messages instead of staying pinned. This required moving all cross-message DO state — not just pendingAgentForks but currentTurn, the wsQueue, and the pending-turn context — into a state.storage snapshot (ensureLoaded/persist), with currentTurn on its own key under a 120 KiB guard. setWebSocketAutoResponse answers the heartbeat ping without un-hibernating. The doorbell already handles waking a DO-evicted cell — same path as a hibernated well.

Phase 5 — sweep the cruft · independent, do any time

Unrelated to the flip but surfaced by the proxy/tunnel diagnosis — dead artifacts worth clearing while the area is fresh. None of it is load-bearing; each item can be removed on its own.

Risks

Per-cell cutover gap
Each cell's bridge is briefly down mid-cutover. Contained to one cell; sequential rollout means a mistake is caught on cell #1, not fleet-wide.
Wake latency
A message to a sleeping cell now waits on doorbell → welld wake → VM boot → dial-in. Comparable to today's inbound-dial wake; not a regression.
Birth path
bake-egg.sh already overlays server.ts and deploy-cell-worker.sh deploys whatever Worker code is in the repo — so cells born after Phase 1 lands are born flipped automatically. Just verify a fresh birth before declaring done.

Net: one hostname per cell, the bridge no longer touches the tunnel or the proxy, and the isWellHost regex class of bug is gone for good. Staged so the fleet is never more than one cell at risk.
