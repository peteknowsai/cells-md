Production readiness — four roots under ten symptoms

Root-cause analysis of the 2026-06-09/10 fleet incident (Zero's ten-item punch list), what shipped the same night, and the structural work that makes the fleet trustable. The headline: nothing about the night was a transport outage — it was drift the system had no way to see.

The one-paragraph version

Mother ran 18 days with a welld service definition and no in-guest supervisor — every cells talk reply to her silently dropped, because materialization is PUT-time-only and her May 22 re-birth landed on a fresh well. The night's "fleet-wide outage" was that drift, plus a 36-minute well wedge, plus an OOM-killed supervisor on a 947MB VM, plus bob waking with an 18-day-stale clock and a pi that has failed every fork since May 23. cells doctor was green throughout, because every check it had stopped at the Mac. The codex route was never down.

How a talk reply actually travels

The await path has four hops, each a separate failure domain — and three of the four failed this month for different reasons:

cells talk X "msg"                                  (Mac CLI)
  └─ well exec → /root/bin/cells talk X --await     (helper inside X's well)
       ├─ POST https://X.cells.md/inbox/append      (CF Worker DO — delivery)
       │    └─ DO → bridge WS → supervisor → pi     (the cell thinks, replies)
       └─ GET http://localhost:8080/agent-wait      (long-poll the supervisor
            ← agent_reply via DO → bridge WS          for the reply)
  • Delivery (DO → cell) is robust — it survived every failure tonight, including redelivery after an OOM kill.
  • The reply leg depends on the in-cell supervisor (well-site.service → bun run server.ts on :8080). No supervisor → instant ConnectionRefused. Dead supervisor mid-poll → the same error after a delay. Both read as "transport broken" from the Mac.
  • Replies are not durable. If the waiter dies, a completed reply is dropped (no local waiter). There is no buffer and no re-poll semantics.

The four roots

Root A — Fire-and-forget materialization

Service definitions, DNA, workers, and clocks are pushed into a cell once — at PUT time, at bake time, at birth time. Nothing ever compares intent against reality again. Re-birth onto a fresh well, a failed apply, an image rebuild, or 18 days of hibernation all silently orphan the cell from its own machinery. Mother (no unit, 18 days), bob (18-day-old supervisor code, 18-day clock skew), and the stale /home/well PATH in her definition are all this one root.

Fix direction (agent-first, not a daemon): a reconcile pass that walks registry → welld defs → in-guest state and repairs drift, run by an agent on a heartbeat — the same shape as pool reconcile. The doctor probes shipped tonight are the detection half; the repair half is the next rung. Birth-special re-registering unconditionally (shipped) closes the re-birth hole specifically.

Root B — No end-to-end observability

cells doctor checked Mac-side state only: local auth, local proxy, patches, shims, postwork files. A fleet whose every cell was mute probed green. Detection of all four failure classes requires reaching inside the wells — which doctor now does (shipped, §5).

Root C — Unmanaged capacity and non-durable replies

Specials run opus with megabyte main sessions in 947MB VMs. A pi spawn that replays the session can OOM the whole unit mid-conversation (mother, 01:11). The protocol then drops the completed reply because the waiter is gone. Three sub-fixes: RAM headroom for specials (wells knob — Pete decision), fork-context capping (known open item, now with a body count), and reply buffering in the supervisor so a re-poll within a window can claim a late reply.

Root D — Emergent (not structural) billing safety

Every well's /etc/environment carries the real metered sk-ant-api03 key, and well egress is permissive. The no-metered-billing guarantee currently depends on a login-shell shim unsetting a variable. Zero is right that this is structural risk. Since pi-on-Max shipped (2026-06-02), the paid-key path in cells is legacy — the clean fix is removing the key from well environments entirely. Decision queued for Pete in NEEDS_PETE.md.

The production-readiness ladder

In order; each rung makes the next one testable. "Production ready" = a fleet that detects its own drift, repairs it, and never loses a completed reply.

  1. Detect (shipped): doctor fleet-transport probes.
  2. Repair: reconcile pass for service/DNA/clock drift — agent-run on a heartbeat, same pattern as pool reconcile. Repairs bob and any future mother-class drift automatically. (Root A)
  3. Durable replies: supervisor buffers agent_replies for N minutes; the CLI helper re-polls by corr_id after transient failures; one retry on the Mac side. Kills the "no local waiter" loss class. (Root C)
  4. Capacity: RAM headroom for specials (Pete: wells create-time knob), fork-context cap (existing open item — it is now a production blocker, not a nuisance). (Root C)
  5. Structural billing safety: remove the metered key from wells, or lock egress. (Root D, Pete decision)
  6. Canary: a scheduled end-to-end talk round-trip against one cell, run by pulse on its heartbeat — the fleet's own pulse check, agent-first. Alerts before a human notices.
