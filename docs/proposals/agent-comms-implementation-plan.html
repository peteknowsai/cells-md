Agent comms — implementation plan

One source of truth per cell. Every "talk" forks main read-only. Same mechanism whether the caller is Pete or a peer cell.

TL;DR

Cells get peer-to-peer agent communication native to the substrate, available to all three harnesses (pi, claude-code, codex). Same mechanism powers Pete's cells talk from the Mac: every "talk" is a read-only fork of the receiver's main thread.

  • Receive: each cell's per-cell Cloudflare Worker recognizes a new kind:"agent" event on /inbox/append and routes it to the cell's supervisor for a fork-and-ask.
  • Send: the on-cell cells talk CLI POSTs to the peer's <name>.cells.md/inbox/append.
  • --await (true RPC): sender includes reply_to + corr_id; peer's response routes back to the sender's own inbox; sender's worker matches by corr_id and unblocks the CLI.
  • --list (discovery): new /peers endpoint on proxy.cells.md.
  • --main (push): escalate the message into the receiver's main thread (writes), instead of fork-and-discard (reads).

Estimated effort: ~1 week for v1 (envelope + worker DO + supervisor fork-and-ask + CLI rewrite + Mac-side path update + discovery). Pattern layer (broadcast/quorum/propose) is another week and not in v1.

What changed since the original spec

The original agent-comms-primitive.md proposed agent messages landing in the receiver's main thread alongside Slack/email. The 2026-05-19 design discussion + audit changed three load-bearing things:

QuestionOriginal specThis plan
The verb New cells-to CLI Extend existing cells talk; no new verb
Landing semantics Agent messages join Slack/email in main Default = fork-and-discard (read main, no write back); --main opts in to main
Pete's cells talk vs cell-to-cell Different mechanisms (cells talk = scratch, agent-comms = main) Same mechanism. One source of truth per cell.
Codex feasibility "Server-side threads, can't fork" Cloned via filename trick, same as claude. Works fine.
Audit summary

All three harnesses support cheap session forking, verified on real cells 2026-05-19. Pi has a native --fork flag. Claude and codex resume by uuid embedded in the session filename — copy the file, resume the new uuid, original stays bit-identical. No pre-prime fallback needed.

The model

One session per cell — its main. Three inbound channels write to it. Two read it via fork. No more parallel "scratch" or "talk-only" sessions.

ChannelDirectionLands in
Slackinboundmain (writes)
Emailinboundmain (writes)
TUIinboundmain (writes)
cells talk <peer> (Pete from Mac)inboundfork (reads main, no write back)
cells talk <peer> (peer cell → cell)inboundfork (reads main, no write back)
cells talk <peer> --main "..."inboundmain (writes) — explicit escalation

If Pete wants something to persist in bob's mind, he uses Slack, email, TUI, or --main. Everything else is a read-only consult: bob sees its full main state, answers, the exchange evaporates.

Why this works

The patterns we want are nearly all one-shot consults: "agree?" (verifier), "what's X?" (expert-query), "FYI Y" (push-notify), "your vote?" (propose). None of them want to mutate the answerer's main mind. Persistence is the exception, handled by an explicit flag.

End-to-end flow

Sender = cell A. Receiver = cell B. Both alive. Worker = the per-cell Cloudflare Worker durable object.

  1. A invokes cells talk B --await "do you agree with my plan to X?" inside A's well.
  2. A's CLI generates a corr_id (ULID), opens a WebSocket to A's own worker (the host-bridge already wires this), and POSTs the envelope to https://B.cells.md/inbox/append with kind:"agent", from:"A", corr_id, reply_to: "https://A.cells.md/inbox/append".
  3. B's worker DO (cli/worker/cell/cell-agent.ts) sees kind:"agent" and posts to B's supervisor at /agent-message with the envelope payload.
  4. B's supervisor (dna/cells/base/site/server.ts) routes by target field:
    • target: "fork" (default): spawn a fork-and-ask using B's harness adapter, capture the response, delete the fork artifacts.
    • target: "main": hand the message to the existing main-thread bridge path (same as Slack/email arrive today).
  5. B's supervisor POSTs back to https://A.cells.md/inbox/append with kind:"agent", from:"B", in_reply_to: corr_id, text: "<response>".
  6. A's worker DO sees an agent event with in_reply_to; looks up the pending corr_id → ws in its map; pushes the response to the waiting WebSocket back to A's well.
  7. A's CLI unblocks and prints the response. Total round-trip on warm cells: ~5s (claude-code measured at 4s for fork+answer; add ~1s for two CF round-trips).

If B is asleep when the inbox POST arrives: existing wake-on-inbox path wakes B (already works for Slack), then the supervisor runs the fork-and-ask.

If A times out before B replies: A's CLI exits with an error; B's eventual reply arrives but no corr_id match — drop and log.

Fork mechanic per harness

Per-adapter additions to dna/cells/base/lib/harness-adapters.ts. Each adapter gets a new forkAndAsk(prompt, opts) → response method. The supervisor calls it; the adapter knows how to fork the harness's main session.

pi

FORK_DIR=$(mktemp -d)
pi --print \
   --fork /root/.pi/agent/sessions/<main-dir>/main.jsonl \
   --session-dir "$FORK_DIR" \
   --thinking off \
   "$PEER_QUERY"
rm -rf "$FORK_DIR"

Pi has a native --fork flag. Pi was designed for this. Cheapest of the three.

claude-code

MAIN_ID=$(cat /root/.cell/claude-main-session)
FORK_ID=$(uuidgen | tr 'A-Z' 'a-z')
cp /root/.claude/projects/-root/${MAIN_ID}.jsonl \
   /root/.claude/projects/-root/${FORK_ID}.jsonl
echo "$PEER_QUERY" | bash -lc "
  export HOME=/root IS_SANDBOX=1
  cd /root && claude --print --resume '$FORK_ID' \
    --permission-mode bypassPermissions
"
rm /root/.claude/projects/-root/${FORK_ID}.jsonl

Claude resumes by uuid in the filename. Copy the JSONL, resume the new uuid. Anthropic prefix cache should hit (same byte prefix).

codex

MAIN_TID=$(cat /root/.cell/codex-main-thread)
# locate main file by uuid suffix
SRC=$(find /root/.codex/sessions -name "*${MAIN_TID}*.jsonl" | head -1)
NEW_UUID=$(uuidgen | tr 'A-Z' 'a-z')
DST=$(dirname "$SRC")/rollout-$(date -u +%Y-%m-%dT%H-%M-%S)-${NEW_UUID}.jsonl
cp "$SRC" "$DST"
bash -lc "export HOME=/root; cd /root && \
  codex exec --skip-git-repo-check resume '$NEW_UUID' '$PEER_QUERY'"
rm "$DST"

Same trick as claude. Original audit was wrong about codex — server-side state didn't matter; codex resumes from the local file. See open question on locating the source file.

The envelope

JSON, POSTed to <peer>.cells.md/inbox/append.

{
  "event": {
    "kind": "agent",
    "from": "nfv-market-cc",
    "to": "pete-advisor",
    "corr_id": "01HQ9XQS9Y4YE8GZ7XKQ3JK0AC",
    "thread_id": "nfv-market-cc:pete-advisor",
    "target": "fork",
    "reply_to": "https://nfv-market-cc.cells.md/inbox/append",
    "hops": 0,
    "sent_at": "2026-05-19T21:14:33.012Z",
    "expires_at": "2026-05-19T21:19:33.012Z",
    "in_reply_to": null,
    "text": "Got a marquee listing in 81428, 20 acres @ $735k. Pete-relevant?"
  }
}
kind
Always "agent". Discriminator alongside slack, email.
target
New for this plan. "fork" (default) = read main, no write back. "main" = write to main like Slack does.
corr_id
ULID. Matches an await's reply to its send.
thread_id
Default: alphabetically-sorted cell pair, colon-joined. Override via explicit --thread.
reply_to
URL recipient POSTs response to. Omitted for fire-and-forget.
hops
Incremented at relay. Drop if hops > 5.
expires_at
For --timeout. Recipient drops if processing starts after expiry.
in_reply_to
The corr_id being responded to. Triggers callback match on sender.

CLI surface

Extends the existing cells talk verb at dna/cells/base/bin/cells. The current implementation (sprites-era tmux-send-keys + sleep 8) gets replaced entirely.

# Fire-and-forget — receiver forks main, answers, response discarded
cells talk <peer> "<msg>"
cells talk <peer> --thread=<id> "<msg>"

# True RPC — sender blocks until receiver responds
cells talk <peer> --await "<msg>"
cells talk <peer> --await --timeout=120s "<msg>"

# Escalate to main — receiver writes the exchange into its main thread
cells talk <peer> --main "<msg>"

# Discovery
cells talk --list
cells talk --list --capability=market

# Inspection
cells talk --inbox [--since=10m]
cells talk --threads
cells talk --thread=<id>

# Audit
cells talk --log [--from=<peer>] [--to=<peer>] [--since=1h]

JSON output by default (cells skill style: { ok, command, data } on success, { ok: false, command, error, diagnosis } on failure).

Build phases

Phase 0 — envelope + worker DO (1–2 days)

Plumb the new event type end-to-end without actually forking yet. Verifies wire format.

  • Add agent-envelope.ts at dna/cells/base/lib/ — encode/decode + ULID generation.
  • Modify cli/worker/cell/cell-agent.ts:219 — recognize kind:"agent"; for target:"fork", POST to supervisor's new /agent-message endpoint; for target:"main", fall through to today's main-thread path.
  • Modify dna/cells/base/site/server.ts — add a stub /agent-message handler that just echoes "stub" back to reply_to. No forking yet.
  • Test: cell A POSTs to cell B's inbox with kind:"agent", target:"fork"; B's stub responds; A receives "stub" back.

Phase 1 — supervisor fork-and-ask, all three harnesses (2–3 days)

The real mechanic: receiver actually forks main, answers, cleans up.

  • Add forkAndAsk(prompt, opts) method to HarnessAdapter interface in dna/cells/base/lib/harness-adapters.ts.
  • Implement for pi (native --fork), claude-code (file-copy + --resume), codex (file-copy + exec resume).
  • Wire the supervisor's /agent-message handler to call adapter.forkAndAsk(text) and POST the response back to reply_to.
  • Test: peer A sends --await message to peer B for each harness; B answers from main context; A unblocks with correct response. Run all 9 combinations (3 harnesses × 3).

Phase 2 — cells talk CLI rewrite + --await callback (2 days)

The on-cell verb works. Pi/codex/claude cells can call it.

  • Rewrite dna/cells/base/bin/cells cmdTalk: drop sprites tmux hack; POST envelope to <peer>.cells.md/inbox/append.
  • For --await: open WS to self's worker, register pending corr_id, block until reply arrives via the WS.
  • Worker DO maintains corr_id → waiting_ws map; on inbound in_reply_to, route to the waiting WS.
  • Add --main, --thread, --timeout flag handling.
  • Test: cell A's harness calls cells talk B --await "X"; A's CLI returns B's response.

Phase 3 — Mac-side cells talk + retire scratch sessions (1 day)

Pete's cells talk from the Mac uses the same flow. Old scratch infrastructure deleted.

  • Update cli/host-bridge.ts: Mac-side cells talk no longer maintains a persistent SSH'd talk-session per cell. Instead, POST to the peer's CF Worker (same path as on-cell).
  • Or keep host-bridge for non-await; route --await through CF. (Decide based on latency measurement in Phase 1.)
  • Delete /root/.cell/claude-talk-session + /root/.cell/codex-talk-thread bake-time creation in scripts/bake-egg.sh (these sessions become vestigial).
  • Delete pi's talk-<cell>/ session-dir spawn in cli/host-bridge.ts + harness-adapters.ts.
  • Test: cells talk mother "hello" from Mac uses fork model; mother's main session is bit-identical before/after.

Phase 4 — discovery + inspection (1 day)

Peers are addressable; recent conversations are queryable.

  • Add /peers endpoint to cli/proxy.ts — reads ~/.cells/cells.json + capability files.
  • cells talk --list calls /peers.
  • cells talk --inbox / --threads / --thread=<id> read from local agent-channel state.
  • cells talk --log queries the substrate audit log.
  • Test: cells talk --list returns alive cells with model + harness.

Phase 5 — guard rails (1 day)

Loops can't run away. Spam is bounded.

  • MAX_HOPS=5 at the worker DO; drop + log if exceeded.
  • Per-pair rate limit at receiver: 1 msg/sec/peer, configurable. Return 429 with retry hint.
  • Expired messages dropped at receiver if expires_at < now.
  • Audit log entry per envelope at both sender's and receiver's workers.
  • Tests: a 6-hop chain drops at hop 5; 10 msgs/sec from A to B returns 429s after the first.

Phase 6 — DNA docs + cleanup (0.5 day)

Cells learn the new verb's full surface from their own docs.

  • Update dna/cells/base/TOOLS.md, CONTACTS.md, CELLS.md with --await / --main / --list usage.
  • Add docs/comms.md — operator-facing runbook.
  • Remove dead refs to the on-cell sprites-era talk implementation.

Total v1: ~1 week. Pattern layer (broadcast, propose-vote, quorum) is roughly another week on top and is out of v1 scope.

Acceptance criteria

v1 is shippable when:

  1. All 3×3 harness pairs work. Peer A's cells talk B --await "X" returns a context-aware response. Verified across all 9 pairs (pi/claude/codex × pi/claude/codex).
  2. Wake-on-await. A sends to sleeping B; B wakes, forks main, answers, A unblocks. Total under 10 seconds on warm welld.
  3. Main isolation. After a fork-and-ask exchange, B's main session file/dir is byte-identical to before. Verified via stat + diff.
  4. --main writes to main. cells talk B --main "X" lands in B's main thread; behaves identically to a Slack message to B.
  5. Pete's Mac path uses the fork model. cells talk mother "X" from the Mac no longer maintains a persistent scratch session; main is byte-identical after.
  6. --list. Returns alive cells with name, status, harness, model, capabilities.
  7. Loop prevention. A → B → A → B → ... drops at hop 5 with audit-log entry.
  8. Rate limit. Per-pair 1/sec cap holds; 429 returned cleanly; sender CLI surfaces the limit.
  9. Audit. cells talk --log --since=1h returns recent envelopes.
  10. Pattern proof. One end-to-end pattern works as a one-liner — suggest verifier: cells talk <sibling> --await "agree with my decision to X?" from any cell.

Open questions

  • Audit log storage. Per-cell worker DO? Operator's Mac at ~/.cells/comms.log? Both? Probably both — worker for transit visibility, Mac aggregation for cross-cell query.
  • Codex source-file lookup. Codex stores rollouts in date-bucketed dirs (~/.codex/sessions/YYYY/MM/DD/); finding "main's file" requires globbing for the uuid suffix. Acceptable but worth a helper. Alternative: cache the full path at bake time alongside the uuid.
  • Capability advertisement. How does a cell write ~/.cells/capabilities/<name>.json? Probably: new endpoint on the proxy (Mac-side) the cell POSTs to. Defer until a cell wants to advertise.
  • Fork dir cleanup on crash. If the harness process crashes mid-fork, the fork file/dir leaks. Add a startup sweep that deletes stale fork-* paths at supervisor boot?
  • Mac-side cells talk: CF or SSH? Same trade as agent-comms: CF is uniform, SSH avoids a round-trip. Decide after measuring Phase 1 latency. Default: CF for uniformity.
  • Concurrency at the receiver. If two peers simultaneously fork B's main, do their forks run in parallel (two harness processes) or serial (one at a time)? Pi/claude/codex aren't strictly memory-cheap to run concurrently. Default: serial queue at the supervisor with a depth limit. Worth a 429 if depth exceeds.

Out of scope (v1)

  • Federation across machines. Substrate roadmap item #9. Single-host for v1.
  • Per-cell identity / keypairs. Roadmap item #1. Transport bearer is sufficient single-operator.
  • End-to-end content signing. Same — needs item #1.
  • Yield-mode --await. The "return a future, don't block" version. Defer until we feel the pain of blocking on slow responses.
  • Pattern layer. cells broadcast, cells quorum, cells talk --propose + aggregation. Ships in v1.1 on top of the four primitives.
  • Cross-cell tool invocation (MCP-style). Beyond freeform chat: structured tool calls. Separate spec.
  • Streaming responses. Receiver streams text as it generates rather than returning a single block. Useful for long answers, but per-harness streaming semantics differ. v2.
