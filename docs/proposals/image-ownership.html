Where the substrate/tenant line goes

A clean rule for what belongs in the base image (wells) versus what cells owns and provisions on top.

The question

"Are there things that should just come with the base image from the get-go that right now you're having to build into eggs, and we should really have the Wells team bake it in?"

Today there are two images: ubuntu-base (wells) and cell-base (cells, layered on top). cell-base is where today's hang came from — wells re-baked ubuntu-base for W.72, and our cell-base went stale relative to it.

This doc proposes a single line — substrate vs tenant — and walks the inventory of every cells-related thing to see which side it falls on.

The principle

Substrate (wells) is anything generic that makes a VM useful: OS, networking, identity injection, lifecycle (start/stop/wake), SSH access. Wells doesn't know what a cell is.

Tenant (cells) is everything that turns a generic substrate into a cell specifically: pi, the agent runtime, DNA (SOUL/CELLS/TOOLS), /root filesystem, cell user, anything pi needs to run.

If a piece is only meaningful in cells's universe, it belongs in cells. If it'd be useful for any tenant (not just cells), it belongs in substrate.

The verdict — what should go INTO the base image

One nudge to the wells team's plate, the rest stays cells's.

bun in ubuntu-base — wells already installs bun on the host (for welld) and inside ubuntu-base for similar reasons; making it part of the published image saves ~10s on every egg bake and is fair for any future tenant to inherit. It's generic enough to be substrate.

Everything else cells-specific stays cells's:

  • pi binary, pi extensions — agent runtime, defines what a cell is
  • DNA files (SOUL/CELLS/TOOLS/etc.) — the cell's personality, pure cells
  • /root + cell user + sudoers — cells-shaped filesystem layout
  • cells-env.sh — cells's env shim

These were in cell-base for speed (one bake → many fast clones). They move to per-egg provisioning. Eggs become the only cells-side cached artifact.

What changes for each side

Wells

One ask: bake bun into the next ubuntu-base rev.

Sized at <100MB, install is just curl -fsSL bun.sh/install | bash in the existing cloud-init. Optional — if you'd rather not, cells installs it per-egg and we lose ~10s/egg. Your call.

Everything else stays as today. Wells keeps owning substrate (OS, networking, lifecycle, identity injection, static IPs, hibernate/wake). Nothing else moves.

Cells

Drop the cell-base image. No more intermediate layered image to keep in sync with ubuntu-base.

Per-egg provisioning script. Wells creates a fresh well from ubuntu-base → cells SSHes in and runs provision-cell.sh (install pi, push DNA, create cell user, write sudoers, configure pi). Result: a fully-formed cell, hibernate-able, claimable as an egg.

Eggs are the cache. Pool depth keeps user-perceived birth fast. cell-base went away; eggs absorb its role.

Cost / benefit

Dimension Today (cell-base) Proposed (per-egg)
Per-egg bake time ~30s (spawn from cached image) ~60-90s (spawn + SSH provision)
10-egg pool refill (cold) ~5min ~10-15min (single-threaded); ~5min if parallelized (W.72 allows it now)
Stale-image drift Real (today's hang) Cannot happen — eggs always provision against current ubuntu-base
Number of cells-owned images 1 (cell-base) 0
Boundary clarity Mushy — cells maintains an image like wells does Clean — wells owns images, cells owns runtime state on top
User-perceived birth Unchanged (warm egg already provisioned) Unchanged (warm egg already provisioned)

The user-perceived experience doesn't change — birth is "claim a warm egg" either way. The cost lives in pool refill time, which is offline work the user doesn't see.

Migration shape

  1. Write provision-cell.sh — single SSH-driven script that turns a fresh ubuntu-base well into a fully-formed cell. ~3-4h of work; mostly reading what cell-base's recipe did and porting it line-for-line into a script.
  2. Update bakeV1Egg — replace fromImage: "cell-base" with fromImage: "ubuntu-base", run provision-cell.sh via SSH post-create, then hibernate. ~1h.
  3. Delete cell-base image (after the migration lands and is verified).
  4. Ask wells to bake bun in (optional, post-migration speed-up).
