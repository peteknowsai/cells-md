The model

Terminology

It's birth and the birthing ritual. No "pregnancy," no "phase 1 / phase 2."

Birth is a return to the original design: a small deterministic handoff in the CLI, then a mother-driven ritual that does the real work. Birth does not need to be fast — ~30s to a minute is fine. The goal is that every agent is always configured correctly.

  1. Generic pool. Pool members are blank eggs — no baked identity, DNA placeholders (__NAME__, __THINKING__, __MODEL_CHAIN__) left intact.
  2. Deterministic handoff. cells birth <name> [flags] claims a generic egg and builds a JSON config blob. It hands mother [name, egg, blob].
  3. Mother follows the birthing ritual. Mother reads the ritual doc and works through it: imprint identity, apply config, register the site service, wire channels + the CF worker, run an end-to-end verification test, report the outcome.
Why this works

The path still largely exists in code. cmdCreate's slow-birth branch already builds a payload JSON and calls runPiWithOutcome("cell-create", …). Two things broke it: the deterministic pool-match in front of it always fails (it matches a variant hash, never the literal v1-generic signature), so it falls through to mother — and then mother's birth skill cold-forks the retired cell-base image. Un-bypass the mother path, repoint the ritual at a claimed generic egg, and the original design is back.

The birthing ritual doc

The ritual mother follows is a single dual-purpose HTML document — docs/birthing-ritual.html:

For a human
Open it in a browser. It's the readable, authoritative explanation of exactly how a cell is born.
For mother
read the file and follow it step-by-step — the same way mother follows a SKILL.md today. HTML is just structured text; an LLM follows it fine.

Same document, two readers. Styled with the shared doc.css. The cell-create prompt shrinks to a thin entry point: "you've been handed a claimed egg and a config blob — read docs/birthing-ritual.html and follow it, substituting from the blob."

Open decisions

Four forks. Recommendations attached — flag any you want to change.

1. Generic pool — uniform, or model-sharded?

The old birth-egg skill baked model + provider per egg ("they shard the pool"). A truly generic pool bakes neither — model becomes a birth-time substitution.

Recommend: truly uniform for V1. One pool, every egg identical. Model/provider applied at birth like everything else. Variant-sharded pools are a later optimization, not a V1 concern.

2. The ritual HTML — a formal pi skill, or a doc the prompt points at?

Pi skills are SKILL.md files with YAML frontmatter (name, allowed-tools). HTML can't carry that frontmatter cleanly.

Recommend: a doc the prompt points at. cell-create.md stays a real prompt; it tells mother to read and follow birthing-ritual.html. This is exactly "use that doc like it would an md file." Tool constraints, if we want them, live in the prompt.

3. Egg baking — deterministic TS, or the mother birth-egg skill?

Two implementations exist: bakePoolMember (TS) and the birth-egg skill (mother-driven).

Recommend: deterministic TS. Egg baking is a background pool-refill job with no per-egg judgment calls — determinism beats an LLM here. Make bakePoolMember generic; retire the birth-egg skill.

4. health-check — fold into birth only, or keep standalone too?

Recommend: both. Its core becomes the ritual's step 7 (birth isn't "done" until verification passes). Keep cells health-check <name> as a standalone command for checking a cell later.

Build sequence

  1. Generic eggs. Strip baked identity from bakePoolMember; bake a fresh generic pool. Confirm an egg has placeholders intact and no committed name.
  2. Write docs/birthing-ritual.html. The dual-purpose ritual — reassemble from birth/SKILL.md + health-check + the channel/worker wiring, repointed to start-from-egg.
  3. Rewrite cell-create.md. Thin entry point: take name + egg + blob, point mother at the ritual HTML.
  4. Fix cmdCreate. Generic-egg claim, default model fix, drop the dead cell-base fallback, hand [name, egg, blob] to mother.
  5. Retire birth/SKILL.md, birth-egg/SKILL.md, egg-birth.md.
  6. Birth a real cell end-to-end. Verify every feature: identity, model/thinking, extensions, site, CF worker, Slack, email, remote talk.
  7. Doc sweep. Update PLAN / BOARD / STATUS to the new birth model with verified ground truth.
