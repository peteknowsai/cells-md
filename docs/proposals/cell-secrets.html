cells secret

Ship a secret to one or many running cells without it ever touching argv, the DNA, or a log line. Built 2026-06-13.

Plain-English summary

A cell is born knowing exactly one secret: CELLS_PROXY_SECRET, its bearer for everything on the subscription proxy. That's injected by the substrate at well-create time and lives in /etc/environment. But cells increasingly need app secrets set after birth — a scoped Convex deploy key, a Stripe key, a per-market token — delivered to a cell (or a whole freshly-born team of cells) that's already running.

Before this, the only way was to hand-roll cells exec <cell> -- sudo tee /some/file with the value sitting in the command line — which lands it in ps, your shell history, and the exec relay's logs. cells secret set is the safe primitive: you point it at a source for the value (an env var, a file, or piped stdin), and the value flows straight into the cell over the exec channel's stdin, never as an argument. It lands as a root-owned 0600 file, and every shell, background job, and the site supervisor pick it up automatically.

Usage

cells secret set <cell[,cell2,…]> <KEY> [--from-env VAR | --from-file PATH | --stdin]
cells secret list <cell>
cells secret rm <cell[,cell2,…]> <KEY>

The value source, in order of precedence:

  • --from-env VAR — read the Mac's environment variable VAR.
  • --from-file PATH — read a file (trailing newlines trimmed).
  • --stdin — read all of stdin.
  • no flag — if stdin is piped, read it; if you're at a TTY, prompt with echo off.

There is deliberately no KEY=VALUE form — passing the value as an argument is exactly the leak this command exists to prevent, so it's refused with a pointer to the safe sources. The team-birth case ("deliver this key to N cells") is a comma-list: the value is read once and fanned out to every cell.

Ship a scoped Convex key to a freshly-born advisor team:

cells secret set advisor-ferro,spec-water,spec-land CONVEX_DEPLOY_KEY --from-env CONVEX_DEPLOY_KEY

Where it lands, and how a cell sees it

Each secret is one file under /etc/cells.secrets.d/<KEY>, owned root:root, mode 0600, whose raw content is the value (no quoting, no encoding — so there are no escaping edge cases). The directory is 0700.

The cell's environment shim, /etc/profile.d/cells-env.sh, sources them: 

if [ -d /etc/cells.secrets.d ]; then
  for _sf in /etc/cells.secrets.d/*; do
    [ -f "$_sf" ] || continue
    _sk=$(basename "$_sf")
    export "$_sk=$(cat "$_sf")"
  done
  unset _sf _sk
fi

Because cells-env.sh is sourced by every login shell, every bash -lc (so: jobs and talk-forks), and the site supervisor's launch script, a secret set this way reaches all of them. New shells and jobs see it immediately (they're fresh processes); a running supervisor picks it up on its next restart.

Safety rails

  • Never in argv. The value is read on the Mac from env/file/stdin and piped to the cell over the exec channel's stdin. The in-cell script reads it with cat. It never appears as a process argument on either side, and the command's own output reports only the byte-length, never the value.
  • Reserved names are refused. Keys that would hijack the shell or loader (PATH, LD_PRELOAD, BASH_ENV, …) or fight substrate-managed auth (CELLS_PROXY_SECRET, the Anthropic/OpenAI bearer names, CELL_NAME, HOME) are rejected. As a second guarantee, the app-secret block is sourced before the proxy-secret re-export, so a substrate name always wins over a colliding app key even if the blocklist ever missed one.
  • Key shape is validated. A key must be a POSIX env-var name ([A-Za-z_][A-Za-z0-9_]*, ≤128 chars). That's also the injection guard: the key becomes both a filename and an export target, so slashes, .., spaces, and metacharacters are impossible.
  • Mac-side only. Like birth and kill, cells secret set lives with the keeper — an in-cell caller can't reach the substrate, so the in-cell cells CLI has no secret verb. A cell's own mother (which runs on the Mac) drives it.
  • Not in the DNA, not baked. Secrets live only on the cell's disk (so they survive hibernation) and are never copied into eggs or the genome. A re-baked or re-born cell starts clean; the operator (or its mother) re-sets what it needs.

What it is not

This is not a secret store or a rotation system. There's no cells secret get — values are write-only from the operator's side (you can see that a key exists with list, never its value). It's the minimal, safe delivery primitive: get a value onto a running cell so its jobs and shells can use it, without leaking it on the way in.
