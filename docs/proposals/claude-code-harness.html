What claude-code is (and isn't)

A cell's harness now has two shapes, and they are genuinely different — not the same cell with a flag flipped.

A pi cell
The full agent. Packages, extensions, channels (Slack/email), a web presence, a model fallback chain. The rich "cell."
A claude-code cell
A coding machine. The claude CLI + an Anthropic model on the Max subscription + codebase access. It doesn't get the cells-project capability stack — no packages, no extensions, none of the cells-side Slack/email machinery. Any channels a claude-code cell has come through Claude Code's own integration surface (MCP servers and the like) — the harness's domain, not birth's. You talk to it, it codes.

claude-code is, in effect, the Anthropic-model harness. It exists to run Claude on the Max subscription, legitimately. A pi cell covers every other model and every other capability.

How Max works with it — the proxy, unchanged

The key finding

cli/proxy.ts needs zero changes. It already does exactly what claude-code needs.

The subscriptions proxy already works like this: a client sends Authorization: Bearer <CELLS_PROXY_SECRET>; the proxy validates it, swaps in the real Max OAuth access token (read from ~/.pi/agent/auth.json, kept fresh by the proxy's own refresh timer), and relays the request to api.anthropic.com. It self-heals on a 401.

The fingerprint problem was never the token — it's the request shape. pi's outbound request shape reads as agent/bot traffic; Anthropic's cat-and-mouse keys on that. claude-code's request shape is genuine Claude Code, because it is claude-code.

So a claude-code cell needs only two env values:

ANTHROPIC_BASE_URL  = https://proxy.cells.md
ANTHROPIC_AUTH_TOKEN = <CELLS_PROXY_SECRET>   # same shared secret pi cells use

claude-code sends genuine Claude Code traffic to the proxy; the proxy swaps in the Max OAuth token and relays. Genuine traffic + the Max token = legitimate Max usage. The proxy is already the sole owner of OAuth refresh — nothing about that changes.

Pi's Max access stays dead — Anthropic's fingerprinting killed it. pi cells route Anthropic models (if ever used) through a paid ANTHROPIC_API_KEY instead, which has zero OAuth-fingerprint surface. Max lives only on claude-code now.

What's on the egg

One uniform generic egg, both harnesses baked on — consistent with "maximally pre-load, switch on at birth." Every egg ships:

  • pi + its .pi/ config structure + the in-tree extensions and packages (as already planned)
  • claude (the Claude Code CLI) + its .claude/ config structure
  • The DNA identity files in both conventions — pi reads its set; claude-code reads CLAUDE.md

Birth activates one harness. It never installs one. No harness-sharded pools.

The birth ritual branch

The config blob's harness field picks the branch. The pi branch is the full ritual. The claude-code branch is short — it skips packages, channels, and extensions entirely:

#claude-code branch
1Imprint identity — __NAME__ into CLAUDE.md and the shared identity files; tmux color.
2Configure model + proxy — set ANTHROPIC_BASE_URL → proxy.cells.md, ANTHROPIC_AUTH_TOKEN → CELLS_PROXY_SECRET, and the chosen Anthropic model + thinking level in the .claude/ config.
3Site service — register it so the cell is talkable + flip the well URL public.
4Verify — the end-test: env present, claude answers a prompt, site serves 200.
5Checkpoint, report outcome, tell the user.

No extensions step, no packages, no cells-side channel/cloud-edge wiring. If a claude-code cell talks to Slack, that's Claude Code's own integration doing it — not something birth sets up.

host-bridge — the real work

This is the one substantial piece. cli/host-bridge.ts is hardcoded to spawn pi --mode rpc and speaks pi's RPC protocol end to end — the switch_session handshake, set_model / set_thinking_level RPCs, the JSON command stream.

A claude-code cell needs a CellSession variant that spawns claude instead, and translates between the cells talk WebSocket protocol and claude-code's headless protocol. host-bridge already resolves the cell's record from cells.json — it just needs to read the harness field and branch.

Needs a spike

The exact claude-code integration shape — driving the CLI in a streaming JSON mode vs. embedding the Claude Agent SDK — should be pinned down with a short spike before committing to host-bridge changes. This is the one genuinely unknown piece; everything else above is mechanical.

Build sequence

  1. Spike. Drive claude headless from a script on the Mac, pointed at proxy.cells.md with CELLS_PROXY_SECRET. Prove two things: the Max path works (genuine traffic passes), and the protocol shape host-bridge will speak.
  2. Egg. Bake claude + the .claude/ structure onto the generic egg, alongside pi.
  3. host-bridge. A claude-code CellSession — spawn claude, translate the protocol.
  4. Birth ritual. Add the claude-code branch to docs/birthing-ritual.html.
  5. CLI + prompt. Make cmdCreate and cell-create.md harness-aware — the blob shape depends on the harness.
