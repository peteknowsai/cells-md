DNA-rev

A content fingerprint that makes "is this egg/cell running current platform code?" a checked, self-correcting fact instead of an invisible one. Designed + shipped 2026-06-13.

Plain-English summary

Every cell is born with a copy of the genome — the platform code in dna/cells/base/ (the supervisor, the libs, the in-cell tools). The word copy is the whole problem. DNA is stamped into an egg when it's baked and into a cell when it's born; after that it's frozen. Improve a lib on the Mac and nothing already alive notices — not the spare eggs in the pool, not the cells already running. The change just… doesn't arrive, and nothing says so.

That silence caused three incidents in one week: a cell running a stale supervisor, another missing a lib module its code expected, and a pool egg that shipped a cell with a months-old jobs lane. Each time the fix existed in the repo and simply hadn't travelled.

DNA-rev gives the genome a version number — a fingerprint of the runtime code, computed from the repo. It's stamped onto every egg and cell at bake/birth/refresh and read back by cells doctor. Now "this egg is two revisions behind" is a fact you can see. And two pieces of machinery you already have act on it: the pool reconciler retires stale eggs and bakes fresh ones; the steward refreshes running cells that fell behind. Stale platform code can no longer ship quietly.

What the rev fingerprints — and what it deliberately ignores

The rev (cli/lib/dna-rev.ts) is a 12-hex SHA-256 over the sync class from cli/lib/refresh.ts — exactly the universal platform surface cells refresh pushes to every cell unconditionally: 

site/server.ts   site/package.json   lib/   bin/   scripts/

Three things are excluded on purpose:

ExcludedWhy
Markdown (*.md)Prose and docs must not churn the rev. The point is content-addressing to behavior, not text — a comment-only edit is a no-op.
Tests (*.test.ts)Never ship to a cell.
Per-cell capability code (.pi/extensions, skills, prompts — the if-present class)A cell carries only what it opted into. Folding these into one global rev would mark a cell that lacks an extension as "stale" the instant that extension changed, and make the steward's auto-refresh storm the whole fleet on any extension edit. They have their own cells refresh-extensions path.

So a rev mismatch means precisely one thing: a cells refresh would change a platform file on this cell — genuine, uniformly-fixable staleness. The fingerprint is LF-normalized and content-only (no mode bits) so it's stable across checkouts and machines, and memoized per process.

The three phases

Phase 1 — visibility

The rev is stamped at every bake/refresh site, all reading the same memoized value:

  • Pool eggs: into pool.json (bakePoolMember) and onto /root/.dna-rev (provisionCellInWell). The pool.json copy lets the doctor judge egg staleness with zero VM wakes.
  • Born cells: bake-egg.sh re-overlays current DNA onto the claimed egg, then stamps /root/.dna-rev — so a cell born from a stale egg reads current, because the overlay made it current.
  • Refreshed cells: cells refresh stamps the rev only on the healthy branch — never before the rollback decision. (Previously the version stamp was written before the health check, so a refresh that health-checked red and rolled back left the cell claiming the new rev while running the old code. Fixed here.)

The in-guest probe (cli/lib/fleet-probe.ts) carries /root/.dna-rev back, and both cells doctor and cells doctor --json show pool + live-cell drift. DNA staleness is kept out of the transport verdict, so it never reads as a transport fault.

Phase 2 — the pool heals itself

The reconciler (cli/lib/reconcile.ts → selectStaleRevCull) retires open eggs whose rev is behind current, then refill bakes replacements at the current rev. It is capped and floored: never empties the pool, and a big rev jump rotates over several passes instead of blackholing births in one.

Phase 3 — running cells heal themselves

The steward (scripts/steward-sweep.sh, fired every 30 min) refreshes running cells that are behind current — at most three per sweep, so a fleet-wide jump rotates over a few sweeps rather than restarting every supervisor at once. This is the durable form of the manual cells refresh <cell> bridge the homezero team had been running by hand.

Two safety rails

Clean-tree gate

Every automatic action — the pool cull and the steward's refresh — gates on a clean working tree (git status --porcelain -- dna/cells/base). An uncommitted edit to a sync file shifts the computed rev; chasing it would stampede the pool and fleet toward uncommitted code. Visibility is never gated: cells doctor still shows the drift on a dirty tree, and the steward alerts ("commit DNA changes to enable auto-refresh") rather than acting.

Conservative rollout

A missing or empty rev — a pre-DNA-rev egg, or a cell whose probe couldn't read the file — reads unknown, and unknown is never treated as stale. Nothing gets mass-culled or mass-refreshed on the day this ships. Existing cells adopt a rev the first time they're refreshed (or reborn); the pool rotates to stamped eggs as it refills. Steady-state drift detection switches on only once an egg/cell actually carries a rev to compare.

Why a separate field, not the variant signature

The tempting design was to fold the fingerprint into the pool's variant signature. Adversarial review killed it: pool matching keys on the literal constant v1-generic (cli/lib/pool.ts), not a computed signature — the signature path it would have extended is dormant V2 code. A separate field marks staleness without touching the live pool-matching key. Content-addressing from the working tree also makes rollback symmetric: git checkout the good tree and the rev flips back, and the same cull + refresh machinery converges in reverse.

Known limits & follow-ups

  • First request after wake. A hibernated cell judged from its last-known rev may serve one request on stale DNA before the next sweep refreshes it.
  • Specials track the base rev. A project mother carries the universal platform surface like any cell; a special that overrides its own non-platform files is out of the global rev's scope by design (specials are hand-managed; cells refresh handles them on demand).
  • Health-check proves boot, not function. Refresh's gate proves well-site restarted, not that every code path works — the same limit the existing refresh has.
  • Comment-in-code still moves the rev. Only whole markdown files are excluded; a comment edit inside a hashed .ts file shifts it. Conservative on purpose.
